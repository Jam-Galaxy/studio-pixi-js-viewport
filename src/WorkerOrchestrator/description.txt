To draw paths on the canvas, we needed a web worker, as waveform drawing is quite slow and starts to slow down significantly after 10 paths. We decided to have a single, large web worker script that could handle any tasks that required a web worker and were necessary for the application (drawing, sound, network, etc.). Why? Because there would be a pool of web workers. Web workers would be created once and used as needed. Specialization would lead to unnecessary workers (with associated overhead) and idleness of existing workers.

This module is a facade over the web worker. It includes a pool and a task queue. It takes responsibility for retrieving tasks from the queue, passing them to workers, and retrieving the results. Therefore, the client code of this module doesn't need to know how to retrieve web workers from the pool and pass them tasks. It only needs to send a task and wait for its results.
